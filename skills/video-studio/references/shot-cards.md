# 镜头配方卡（10 张）

> 何时读：写到某一段卡住了（"这段该多长？字幕放哪？要不要配音效？"），或想让片子
> 的动作语言统一时。查完就回去改 `film.json` / `scenes.py`，不要把这张表当模板套。

## 1. 这张表解决什么

`scene-grammar.md` 回答"10 类构图怎么选"，但真实制作里卡住人的通常不是构图，而是：

- 这一段该多长？（太短观众没读完，太长片子散架）
- 画面上已经有标题了，字幕还压不压？
- 这里要不要一个音效？要哪种、落在第几秒？
- 动效该明显还是该收敛？

这些知识原来散在四个文件里（scene-grammar 的时长门槛、designkit 的动效、audio 的音效、
aesthetic-rules 的判例），每做一段都要翻一遍。现在按**有名字的镜头意图**配好默认值，
查一张卡就能开工。

三条纪律：

1. **卡是候选池，不是模板**：每张卡给一组合理默认，不是唯一答案；
2. **不新增外观**：卡只引用已有的 10 类构图 + 已有音效配方 + 已有动效曲线，
   抄这张表不会让片子变成"某套模板"（本技能没有内置风格表，外观只来自 `design.json`）；
3. **卡能被机器检查**：构图必须在 `grammar.SCENE_TYPES`、音效必须在 `sfxkit.REGISTRY`、
   动效必须在 `designkit.EASES`——自检第 108 条盯着，改枚举后卡库指向不存在的东西会立刻红。

## 2. 卡表

| 卡号 | 名字 | 什么时候用 | 构图 | 长度（短/建议/长） | 字幕 | 动效 | 音效 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| C01 | 开场钩子 | 第一段，要让人在 3 秒内知道这片子讲什么、并且愿意看下去 | `hero` | 2.4 / 3.2 / 4.5 s | none | out5 / soft | 0.00s whoosh、0.35s impact |
| C02 | 数字定格 | 有一个能代表全片量级的数字，要让它单独占一屏 | `stat` | 3.2 / 3.8 / 5.0 s | bottom | out3 / still | 0.00s ui_blip |
| C03 | 要点清单 | 3–6 条并列信息，每条要说清但不需要展开 | `list` | 3.0 / 4.2 / 6.0 s | bottom | out3 / soft | 无 |
| C04 | 左右对撞 | 两种做法/两个方案的正面对比，观众需要在同一屏上同时看到 | `compare` | 4.0 / 5.0 / 7.0 s | bottom | inOut3 / soft | 0.00s whoosh |
| C05 | 顺序推进 | 有明确先后的 3–5 步，观众要看到「走到第几步了」 | `process` | 4.0 / 5.5 / 8.0 s | bottom | out3 / soft | 0.00s whoosh |
| C06 | 金句停顿 | 一句能被单独记住的话，说完之后要给观众留白 | `statement` | 2.6 / 3.4 / 5.5 s | none | out5 / still | 无 |
| C07 | 引语出处 | 要借第三方的嘴说话，且必须让人看到是谁说的 | `quote` | 4.0 / 5.0 / 7.5 s | bottom | out3 / soft | 无 |
| C08 | 数据条 | 3–6 项可比的量，要让人一眼看出谁高谁低 | `chart` | 4.5 / 5.5 / 8.0 s | bottom | out3 / soft | 无 |
| C09 | 章节换气 | 换章节时的一次呼吸，让观众知道「进入下一部分了」 | `chapter` | 2.2 / 2.8 / 3.6 s | none | inOut3 / soft | 0.00s impact |
| C10 | 收尾落点 | 最后一段，把全片收住，并留出署名/出处的位置 | `outro` | 2.4 / 3.0 / 4.5 s | none | out5 / soft | 0.00s impact |

- **C01 开场钩子**：不要在这张卡上叠字幕：封面已经有标题与副标，第三行字会挤掉留白。
- **C02 数字定格**：数字与单位必须来自 FACTS.md 实测值；凑数用的数字宁可换成 list。
- **C03 要点清单**：超过 6 条会被截断；真要 8 条就拆成两段，不要指望观众记住 8 行。
- **C04 左右对撞**：不适合「我们 vs 他们」式贬低：对比要同维度，两边条目数尽量相等。
- **C05 顺序推进**：步骤超过 5 个会被截断；长流程拆成多段，每段只推进几步。
- **C06 金句停顿**：金句一多就不叫金句；全片不超过 2 张，且不要连着放。
- **C07 引语出处**：出处不能省：没有出处的引语在本技能口径里等同于编造。
- **C08 数据条**：量纲要一致（别把 % 和 万 放同一组）；序列 < 2 条会被绘制器退成 stat。
- **C09 章节换气**：章节卡不要每段都放：连续两张会让片子变成 PPT 目录。
- **C10 收尾落点**：收尾字与片尾出处卡别抢同一个位置；有 credit 时先给 credit 留时间。

## 3. 怎么用

```bash
# 看全部卡（表 + 误用清单）
python <SKILL_DIR>/scripts/shotcards.py --list

# 按意图找卡
python <SKILL_DIR>/scripts/shotcards.py --intent "开场,钩子"

# 取一张卡的完整配置
python <SKILL_DIR>/scripts/shotcards.py --id C01
```

在代码里套用（只填**没写过**的键，不覆盖手写值）：

```python
import shotcards as SC

scene = {"id": "l05", "text": "2015 年，错误率降到 3.6%。"}
SC.apply("C02", scene)      # -> 只补 type=stat / min_dur=3.8，不改已有 text
```

> `apply()` 故意只填空值：卡是默认，人是终裁。覆盖手写的 `type` 会让"我明明改了"变成玄学。

## 4. 选卡的判断顺序

1. 这一段**要让观众记住什么**？（数字 → C02；步骤 → C05；对比 → C04；一句话 → C06）
2. 这是片子的**什么位置**？（开头 → C01；换章 → C09；收尾 → C10；正文 → 其余）
3. 这段**容量够不够**？（`list` 超 6 条、`process` 超 5 步、`chart` 超 6 条都会被截断，
   拆成两段而不是硬塞）
4. 最后才看动效与音效：它们是锦上添花，构图错了救不回来。

## 5. 常见误用

见上表每张卡的 `avoid` 列——那一条比 `intent` 更值得读，因为它写的是"这么做过之后
发生了什么"。
