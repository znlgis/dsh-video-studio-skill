# 审美准则（判例式）

> 这一份不是参数表，是**判例**。阈值（字号、色相数、响度）在 `quality-gates.md` 与
> `appearance.md` 里；这里写的是「为什么这一条存在、违反了长什么样、怎么自己检查」。

## 怎么用

1. 编号体系：`R`（节奏）/ `Q`（质感·运镜·构图）/ `S`（声音）/ `C`（文案）/ `P`（流程）。
   **编号一经发布不重排**，新增条目只往后追加——这样历史报告里的「R3」永远指同一条。
2. `--stage review` 出的评审包里，这些条目就是评审者要逐条打勾的清单。
3. 每条三要素：规则（一句可执行的话）+ 判例（真实返工经过）+ 自检（可回答的问题）。
   缺任一条就不许进这份文件——没有判例的规则迟早退化成标语。
4. 准则**可以被有意识地违反**（风格需要时），但每次违反都要写进该项目说明：违反了哪条、
   为什么。悄悄违反 = 事故。

## R — 节奏

### R1 关键信息落定后必须呼吸
规则：承载信息的画面（标题、数字、图表全貌）落定后静止 ≥1s 再切镜；品牌/片名的落定优先于普通内容卡片。
判例：初版把 hold 均摊给所有段，结果金句段干等、结尾片名一闪而过。改成「落定类 ≥1s、过渡句可短」后才顺。
自检：把每个想让观众记住的画面挑出来——它有没有一个完整静止的时刻？停顿给的是关键信息，还是随手给了普通元素？

### R2 速度感来自加速度，不是匀速快
规则：飞入/滚动一律非线性缓动 + 非均匀错峰；同类元素批量入场要越来越快，或绑一个物理隐喻（发牌、落库），满板后静止 ≥0.5s 再切。
判例：把卡片做成匀速下落时，反馈第一句就是「像 PPT」；改成加速 + 末尾停顿后一次通过。
自检：全片有没有任何元素在做匀速直线运动？批量入场末尾有没有静止呼吸？

### R3 节奏宁慢勿快，初版默认放慢一档
规则：开场主体动作弧 ≥3s；模拟真实交互（打字、筛选、点击）按真人操作速度走；排时间轴时预先给 hold 留帧预算。
判例：本仓库历史返工里，指向「太慢」的反馈为 0 次，指向「太快」的占多数。这是单向偏好，可以放心往慢调。
自检：把每一段当第一次看，哪里没看清？交互段落自己能不能跟着做一遍？

### R4 卡点约束时机，不放大幅度
规则：强节奏 BGM 下，切点落拍不等于逐拍打画面；作用于整画面/相机层的冲击（整画 scale 泵、震屏、闪帧）全片 ≤3 处，其余拍点只动元素层。
判例：把每个 kick 都映射成一次画面冲击，观感是镜头随节奏抖，用户原话是「影响观感」。正确做法是 kick 命中表只当**候选池**，从中挑最强的 2–3 处。
自检：高能段任取连续 8 拍逐帧回放——整画面 scale/位移是否在逐拍脉冲？全片整画面冲击数得过来吗？

## Q — 质感·运镜·构图

### Q1 每帧是纯函数，随机必须有种子
规则：`draw` 里禁 `random`/`time()`；需要噪声用 `filmkit.hash2/hash3/vnoise`，同一帧号永远画同一张图。
判例：一旦画面混入 `random`，`--resume` 分块渲染会拼出接缝，金帧回归也永远对不上。
自检：同一帧渲两次，diff 是否为 0？`--jobs 4` 拼出来的片子有没有肉眼可见的接缝？

### Q2 缓动只用一套嗓音
规则：一部片只用一个品牌的缓动族（`EASES` 里挑 1–2 档），过冲/squash 量定好后全片复用；混用两套读作拼盘。
判例：商业片里既用 `outBack` 又用 `out3`、还手写一段直线 ease，观感是每个镜头像不同人做的。
自检：用三个词描述这部片的动效性格，和题材对得上吗？入场/转场/停留是不是同一套节奏？

### Q3 镜头要稳，默认不加抖动
规则：图文/UI 类片默认零手持抖动；抖动只在明确追求纪实感的暗场段用极小值，且必须渲帧自查确认。
判例：给整片加了极轻的相机噪声，反馈是「有小抖动不知道怎么回事」；去掉后零投诉。
自检：逐镜头看渲出来的帧，有没有任何非叙事意图的抖动？

### Q4 高光/扫光宁缺毋滥
规则：glint/泛光/扫光不群发——批量元素入场靠运动本身；保留的光效必须被元素圆角裁剪，且一个镜头最多给主角一次。
判例：给每张卡片都加一道泛光划过，两次被否决。单点、高质量、裁进圆角之后才留得住。
自检：数一数全片光效次数——超过主角一次了吗？每处是否被圆角裁住？正常速度回放自己觉得好看吗？

### Q5 开场只给一个主角
规则：开场宁少而聚焦——一个主角元素、一条完整动作弧（聚焦→推近→悬浮→归位），多元素群舞撑不起第一印象。
判例：开场塞了三个并列卡片 + 标题 + 数据条，第一句反馈是「不知道先看哪里」；砍到单卡后结构再没动过。
自检：开场镜头里有几个想让观众看的东西？超过一个就先砍。

### Q6 字幕与大字永不出安全区
规则：正文 `y ∈ [58, 974]`、字幕带 `y ∈ [872, 1030]`；任何放大字号的改动之后都必须重跑安全区自查。
判例：设计里把字幕字号从 46 提到 56、又把 `plate_alpha` 设 0，两条门禁都绿，但成片字幕贴底被裁。
自检：改过 `visual.subtitle` 里任何字段后，`qa_text_safe` 有没有按**本片设计**真的重跑过？

## S — 声音

### S1 旁白优先是硬行为，不是口号
规则：混音后必须实测人声活跃区的人声/背景比，不足 12 dB 就补压背景；不要靠调小配乐「感觉一下」。
判例：配乐基线写成 -1.5 dB 时人声与背景几乎等高，观众要费力分辨台词；改成 -12 dB + 侧链 + SNR 兜底后才听清。
自检：`--stage audio` 输出里那条人声/背景实测值是多少？配乐有没有在说话处让位？

### S2 声音跟着画面走，靠提示点而不是手写秒数
规则：音效落位一律登记在 cues（`scenes.py` 的 `cues()` 或 `film.json` 的 `sfx.cues`），改画面节奏时提示点自动跟着改。
判例：早期版本把音效秒数写死在混音脚本里，改一句台词后所有音效晚 0.4 秒，全片重对一遍。
自检：改了台词/`hold` 之后音效还需要手工挪吗？`cues.json` 里是语义锚点还是绝对秒数？

### S3 该有声音的地方不许只有底噪
规则：转场、落定、切换这三类时刻必须有声音设计（哪怕很轻）；长静音要么是刻意的呼吸位，要么是 bug。
判例：一段 6 秒产品展示只有配乐垫底，观感像忘了做。补一声极轻的 whoosh 就活了。
自检：整片听一遍，有没有哪个转折点是干的？静音段能不能说清是刻意还是遗漏？

### S4 响度/真峰以实测为准
规则：交付必须给积分响度与真峰两个数（-16 LUFS / ≤ -1 dBTP），并说明是哪条命令测的。
判例：只看波形「看起来不小」就交付，成片在手机上比别的视频轻一半。
自检：QC-REPORT 里这两个数的实测值是多少？是不是这一版测的？

## C — 文案

### C1 朗读文本与上屏字幕是两个字段
规则：`text` 写给耳朵（自然口语），`sub` 写给眼睛（短、可读）；不要把一句话切成两半塞进同一个字段。
判例：把长句直接当字幕，一屏挤 4 行、观众读不完就被切走。
自检：每条字幕在一屏停留时间内读得完吗？读起来像人话还是像文档？

### C2 上屏的每个数字都要有出处
规则：画面里出现的数字/年份/排名，必须在 `FACTS.md` 有一行对应来源；没有出处就换说法或删掉。
判例：旁白说「三年」、画面写 2019–2021（实际四年），被指出来整套返工。
自检：随便挑画面上三个数字，能在 FACTS.md 里找到出处吗？

## P — 流程

### P1 先问诊、再提案、后出片
规则：制作方式/题材/时长/气质/声线/配乐没答完不许进渲染；`design.json` 没 `--confirm` 冻结不许渲 `frames`/`all`。
判例：跳过提案直接渲，出来是又一套默认皮肤；用户真实诉求（深色、冷、少装饰）全靠返工猜。
自检：这一版的 `design.json` 是谁确认的？提案的候选有没有并排看过？

### P2 验收贯穿全程，不是最后一步
规则：每个镜头都出静帧人眼验收再往下做；交付前必须跑 `--stage review` 并让**干净上下文**的评审者过一遍清单。
判例：整片渲完才第一次看，发现问题时 36000 帧已经白跑；制作方自检有确认偏差，独立评审才抓得到我以为我做了的那部分。
自检：评审包 `work/review/` 生成过吗？那份清单是同一个上下文自己打的勾，还是独立评审给的？

### P3 门禁的 skipped 不等于通过
规则：报告里的 `skipped` 必须逐条说明为什么没执行；`--strict-gates` 下 skipped 算失败。
判例：缺 `cv2` 时锐度比门禁记 skipped，报告结论仍写所有门禁通过，交付后才发现文字发虚。
自检：这一版 QC-REPORT 里 skipped 有几条？每条的为什么没跑写清楚了吗？

### P4 改动要知道要重跑什么
规则：改剧本/`scenes.py`/设计之后不要 `--resume` 复用旧产物；用 `--stage explain` 看最小重跑集合。
判例：改了台词继续 `--resume`，拼出画面对不上旁白的片子，还过了容器门禁。
自检：这一版的重跑命令能重现它吗？旧分块/旧缓存有没有被误用？
