# 最佳实践 / 反模式 / 事故复盘

## 一、20 条最佳实践（按收益/成本排序）

| # | 做法 | 为什么值 |
|---|---|---|
| 1 | **时间基准先算死，写成一份文档，所有子系统引用同一模块** | 后面一切对齐靠它；改一次全片受益 |
| 2 | **内容与风格解耦**：一份内容 + 一组风格参数 | 母版切换零成本，审美决策可推迟到"看到图再定" |
| 3 | **音频实测反推时间，绝不按字数估算** | 字幕漂移是观众最先察觉的瑕疵 |
| 4 | **字幕文本与朗读文本分离**（`sub` 短 / `text` 长） | 上屏可读性与朗读自然度是两个约束 |
| 5 | **提示点由画面声明、由声音消费** | 音画对齐从"感觉"变成"数据" |
| 6 | **分块键用绝对帧号**（`seg_025200_025560.mp4`），拼接时显式检缺口；再存一份**计划指纹**（`_plan.json`） | 唯一一次"少了 183 秒还不报错"的根因。只按"文件在不在"跳过还会导致"改了台词却复用旧画面"——计划指纹不符会**拒绝拼接**并提示删目录 |
| 7 | **JPEG q94 截图替代 PNG**（浏览器方案） | 215 → 55 ms/帧，PSNR 41–44 dB 肉眼无差 |
| 8 | **worker 复用浏览器、出错才重建、finally 必关** | 每块开新页会把进程堆到 28 个、内存 2.7 GB |
| 9 | **前瞻限幅器补响度，不整体拉高** | 只压峰值不改主体响度 |
| 10 | **AAC 编码前预留 1.4 dB 峰值余量** | AAC 会把真峰推高约 0.9 dB |
| 11 | **物理建模激励用加速度不用位移** | click 类质心从 200 Hz 提到 900+ Hz |
| 12 | **每条音效自动出分析图 + QC 阈值** | agent 听不见，但能看图 |
| 13 | **循环环境音用频域整周期噪声** | 首尾天然无缝 |
| 14 | **静态预渲染 + 动态廉价图层 + 相机是裁切窗口** | 单帧从数秒降到可控 |
| 15 | **已验收画法沉淀成构建器函数** | 后写的人只能"调用"不能"发明"，风格一致性靠结构保证 |
| 16 | **Warp 面积累积时间重映射** | 让"后期插入停留"不破坏音画同步 |
| 17 | **段尾必须停住，用逐像素比对验证** | 观众"没看清就被切走"是最常见差评 |
| 18 | **事实核查当独立任务派出去，有编号有黑名单** | 抓到 8 处硬伤，其中 2 处会被评论区顶到第一 |
| 19 | **写入边界 + 接口先写死 + 一份施工文档** | 多 agent 并行不打架的三个前提 |
| 20 | **交付文档如实声明已知边界** | 把"局限"变成可信度，而不是藏起来 |

## 二、17 条反模式（全部有实证）

| # | 反模式 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | 单条 ffmpeg 命令上百个输入混流 | 非确定性静音（三次跑出正常/静音/正常），成片只有前 15 s 有声 | numpy 精确累加 + 分段 RMS 自检 |
| 2 | 以"第几块"命名分块 | 补渲后重号，25 块拼出 417 s（缺 183 s）**且不报错** | 绝对帧号命名（`seg_<起始帧>_<结束帧>.mp4`）+ 排序 + 缺口检测 + 计划指纹 |
| 3 | 用 RMS 近似 LUFS | 误差 6–8 dB，验收形同虚设 | ebur128 / BS.1770 实测 |
| 4 | 先 astype(float32) 再判 dtype | 混音峰值 +92 dBFS | 先判 dtype 再归一 |
| 5 | 把文档数字当验收标准 | README 写 397 cues，产物 370 | 用产物 JSON 反查文档 |
| 6 | 字幕时长按字数比例分配 | 252 处交叠 | TTS 句边界为窗，窗内按标点切 |
| 7 | 场景函数/音频合成/主流程塞进一个文件 | 无场景注册、无并行、无质检、无断点续渲 | 引擎/场景/音频/渲染器四层分离 |
| 8 | PNG 截图做逐帧渲染 | 215 ms/帧 | JPEG q94 → 55 ms/帧 |
| 9 | 每块开一个新浏览器 | 进程累积到 28 个、内存 2.7 GB、渲染卡死 | 长活 worker 复用 + finally 关闭 |
| 10 | 字段改名不留兼容/不跑冒烟 | 全片幕首淡入与图名框**静默失效**，零报错 | 改名后必跑 snap + 元素存在性检查 |
| 11 | 脉冲/位移激励做打击音 | 质心 ~200 Hz，像闷鼓 | 用接触力的二阶导 |
| 12 | QC 判据键名不统一 | `mid_2k6k` / `mid2k6k` 不一致 → 检测恒为 0，等于没检测 | 键名集中定义 + 单测 |
| 13 | 并行写同一批产物 | 读到半成品 mp3 | 产物级串行，或按文件分区 |
| 14 | 音频用单声道总线后复制成双声道 | 损失立体声场 | 全程 float32 立体声（配乐做宽度） |
| 15 | 静态图叠加忘了 `-loop 1` | 时间轴被截成 1 帧 | `-loop 1 -framerate ` |
| 16 | 靠"注意准确性"这种叮嘱做质量 | 无法验收 | 事实核查有编号、出处、黑名单三件套 |
| 17 | 把颗粒烘进底图，再用 NEAREST 逐帧缩放取景 | **满屏噪点沸腾**（用户原话"明显的抖动感"），而单帧闪烁门禁全程报 0 | 端点预烘 + `Image.blend` 取景；颗粒留在底图但只走平滑重采样（见复盘 ④） |

## 三、五个 bug 复盘（最值得读）

### ① 音轨中断：成片只有前 15 秒有声

**现象**：成片 mp4 开头约 15 秒有声音，之后全程静音。

**根因**：混音用单条 ffmpeg 命令处理 **109 个输入**（55 条配音 + 16 段环境音 + 2 段配乐）。Windows 上 ffmpeg 输入线程池存在竞争：循环输入与大量 `-i` 同时打开时，偶发某个输入尚未就绪就被读取，混音滤镜收到空流，导致后续输出静音。**同样命令连跑三次：正常 / 静音 / 正常。**

**修复**：改为 numpy 精确叠加——每个音源解码为 48k float32 PCM（带缓存）→ 按时间轴精确写入总线 → 归一化 + tanh 软限幅 + 淡入淡出 → 写 WAV，并内置每 20 s 的 RMS 自检。

**教训**：**"确定性"是程序化视频的第一性要求**。任何"同样输入跑两次结果不同"的环节，都要换成纯 numpy/纯 JS 显式实现，并配一个能检出"错了"的自检。

### ② 混音 +92 dBFS

```python
x = x.astype(np.float32)      # ← 先转 float32
if x.dtype == np.int16:       # ← 这个分支永远不成立
    x = x / 32768.0
```

int16 的归一化分支永远执行不到，采样值还是 ±32768 的量级。

**教训**：这类 bug 不报错，只会在"叠加峰值 +92 dBFS"这种数字上暴露 → **混音脚本必须打印中间峰值**。

### ③ 全片淡入静默失效

```js
const localT = t - act.t0;        // undefined
const inP = clamp(localT / 0.5);  // NaN
if (inP < 1 && act.i > 0) { ... } // 永远不成立
```

字段从 `t0` 改名成 `start` 后，全片十幕的淡入特效与所有图名框**静默失效**。没有任何报错，画面照常渲染，只是"少了一点东西"。

**教训**：质检分两类——**"不能有"**（闪烁、重叠、出画、削波）和**"必须有"**（图名框、淡入、字幕、每段至少一个动态元素）。后者更难，因为需要一份"应然清单"。

### ④ 整片"发抖"：颗粒 + NEAREST 取景

**现象**：成片从头到尾有轻微抖动感，用户说"有明显的抖动感"，但 `flicker_scan` 0 条、
VMAF 97+、SSIM 0.999——所有现有门禁都说没问题。

**根因**：`_bg()` 把颗粒（逐像素 hash 噪声）烘进了静态底图，逐帧再用
`EXTENT + NEAREST` 按缓推比例 `s` 取景。NEAREST 的采样网格随 `s` 整像素跳变，
颗粒图案整体错位 1px。实测背景-only 相邻帧差 **4~6 灰阶**（整屏低幅位移），
而"单帧闪烁"判据比的是前后帧平均亮度——压根看不到这种位移。

**修复**：`s=1.0` 与 `s=1+push` 两个端点各烘一张 BILINEAR 底版（每张约 60 ms，一次性），
逐帧 `Image.blend(lo, hi, (s-1)/push)`（约 4.4 ms/帧）。实测相邻帧差降到 **0~1 灰阶**。
为什么不用 BILINEAR/BICUBIC 直采：整帧重采样 29/64 ms，超 15 ms 单帧预算。

**教训**：**"能出片 + 指标好看"不等于"看着不抖"**。质检判据要按**瑕疵的物理类型**分类：
亮度型（闪烁/黑帧）、位移型（抖动/漂移）、时序型（同步/丢句）。缺哪一类，
那一类就会一直漏。补判据的同时补一条 `selfcheck` 断言（第 68 条），否则下次改回 NEAREST 没人发现。

### ⑤ 修好颗粒以后还在抖：慢速亚像素位移 + 整数取整

**现象**：① 的 NEAREST 修复上线后，底图帧差已经 0~1 灰阶，用户仍然说"画面在抖"、
"大部分画面有明显的抖动和移动"，而 `flicker_scan` 依旧是 0。

**根因**：镜头缓推是**慢速**位移。`_push_scale` 把 push（0.02~0.14）均摊到整段，
`_View.x/y` 再 `int(round())` 取整 —— 4% 的推镜在 8 秒里只走 7px，就是 0.03px/帧，
取整后变成「每 5 帧整块跳 1px」。实测文字锚点位移频率：push 0.02 → 0.67 次/秒、
0.04 → 1.25 次/秒、0.14 → **4.4~12 次/秒**；一次跳跃有 5000+ 个像素差 >40 灰阶。
另外 `quote` 的引号还在做 6px 上下浮动（0.1px/帧），同样碎成 1px 台阶。

**修复**：
- `_view()` 恒 `_View(1.0)`：**前景不跟相机**，只有底版按端点 blend 缩放；
- 默认 `push=0`（采样档位只剩 0.0），默认设计段落中段是整帧静止；
- 引号的"呼吸"改成只调透明度，不再位移；
- 所有装饰描边在素净母题下 `_lw()` 抬到 6px，`width=1/2` 的线一律不画或加粗。

**教训**：**抖动不是"动得多"，是"动得比一个像素还慢"**。要么不动（静止就是静止，
整像素永远不会抖），要么动得够快（>= 30px/s，取整看不出台阶）。介乎其间的慢速位移，
在 1x 光栅上只能靠超采样解决，而超采样超预算 —— 所以这一版选择"不动"。
另外两条产品约束也来自这次反馈：**默认设计不带细线**（细线是母题/底纹/HUD 三条来源，
压缩后最容易显脏）、**默认不推镜**（推镜只会把上面的台阶放大到整屏）。
护栏：`selfcheck` 第 71、72 条。

## 8. 常见故障速查

| 现象 | 根因 | 修法 |
|---|---|---|
| 后半段全程静音 | ffmpeg 多输入混流竞争 | 改 numpy 总线 `bus[i:i+n] += src*gain` |
| 混音爆音/削波 | 先 `astype(float32)` 再判 dtype，归一化分支不执行 | **先判 dtype 再转**，并打印中间峰值 |
| 字幕越出画面被裁 | 字幕带贴底 | `SUB_BAND` 上移到 872，`base_y` 夹紧 |
| 文字发虚 | cv2 中间文件二次压缩 | 改 rawvideo 直通 + CRF18，用锐度比验证 |
| 音画不同步 | 按字数估时长 | 改实测时长驱动 |
| 字幕交叠 | 按字符比例分配字幕时长 | 以 TTS 句边界为窗，窗内按标点切 |
| 全片该有的淡入/图名框消失 | 字段改名没跑冒烟 | 改名后必跑 `snap`；质检加"元素存在性" |
| 渲染越跑越慢 / 内存涨 | 每块开新浏览器没关 | 复用会话 + `finally` 关闭 |
| 拼出的片子缺一段还不报错 | 分块按"第几块"命名 | 按**绝对起始帧**命名 + 显式缺口检测 |
| **请求 524 帧却只出 488 帧** | `-shortest` 按较短一路（音频）截断 | 去掉 `-shortest`，显式 `-t <视频时长>` + 校验音视频时长差 < 0.05 s |
| 产出 13 小时的怪物文件 | `-stream_loop -1` 让 `-shortest` 失效 | 显式 `-t`，别依赖 `-shortest` |
| BGM 混音后掉 6 dB / 听不清 | `amix` 默认 `normalize=1` 会按输入数均分 | `amix=...:normalize=0` 再 `loudnorm=I=-16` |
| 旁白整体偏移 ~0.6 s | `adelay` 铺轨有系统性偏移 | 别用 adelay，改 numpy 按采样点写位 |
| 烧录字幕字号小得看不清 | SRT 交 libass 按 `PlayResY=288` 排版 | `FontSize/MarginV` 要 ×3.75，或直接用 ASS 指定 PlayRes |
| ASS 字幕位置全乱 | Format 行漏了 `MarginL/MarginR/MarginV` 字段 | ASS 头 Format 行字段顺序必须与 Dialogue 完全对应 |
| 渲染出上一部片的内容 | `sys.path` 顺序导致 import 到旧模块 | 用绝对路径 + 每次全新进程；子进程别继承父进程模块缓存 |
| 画面里 ✓ × ↵ 显示成方框 | msyhbd 缺这些字形 | 用矢量画（ImageDraw 线条），不要用符号字符；或先跑 `K.check_glyphs` |
| **改了台词但配音没变** | TTS 缓存只判断"文件存在" | text/voice/rate/pitch 哈希必须写进 `*.mp3.json`；只判存在性的旧缓存要 `--force-tts` 一次 |
| **长句字幕读到一半消失** | `sub_window` 把 t1 钳在 `voice_start+5.2` | 默认覆盖整句；要钳短显式传 `max_hold` |
| **--stage qa 也重渲全片** | stage 分发写成 `in ("all","frames","mux","qa")` | 每个 stage 独立；qa 只读成片 |
| **concatenation 打不开分块** | concat.txt 里写相对路径，ffmpeg 按自己 cwd 解析 | 写**绝对路径** |
| 成片比 silent.mp4 慢一倍 | mux 对已编码视频又编一遍 | `-c:v copy`（默认）；只在要改分辨率时 `reencode_video=True` |
| 每帧渲染慢 2–3 倍 | 每帧重新 `wrap_cn`（中文逐字测宽） | 用 `K.wrap_cn_cached` / `K.text_w_cached` |
| 混音偶发爆表 | 归一化分支没执行 / 叠加峰值 >1 | `AudioBus.mix()` 会打印叠加峰值并软限幅，峰值 >0.97 报警 |
| **成片音轨变成 96kHz** | mux 没指定 `-ar`，loudnorm 内部升到 192kHz 后 AAC 取了 96k | mux 显式 `-ar 48000`（内置于 mux，selfcheck 第 12 条守着） |
