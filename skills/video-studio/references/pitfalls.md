# 最佳实践 / 反模式 / 事故复盘

## 一、20 条最佳实践（按收益/成本排序）

| # | 做法 | 为什么值 |
|---|---|---|
| 1 | **时间基准先算死，写成一份文档，所有子系统引用同一模块** | 后面一切对齐靠它；改一次全片受益 |
| 2 | **内容与风格解耦**：一份内容 + 一组风格参数 | 母版切换零成本，审美决策可推迟到"看到图再定" |
| 3 | **音频实测反推时间，绝不按字数估算** | 字幕漂移是观众最先察觉的瑕疵 |
| 4 | **字幕文本与朗读文本分离**（`sub` 短 / `text` 长） | 上屏可读性与朗读自然度是两个约束 |
| 5 | **提示点由画面声明、由声音消费** | 音画对齐从"感觉"变成"数据" |
| 6 | **分块键用绝对帧号**（`seg_025200_025560.mp4`），拼接时显式检缺口；再存一份**计划指纹**（`_plan.json`） | 唯一一次"少了 183 秒还不报错"的根因。只按"文件在不在"跳过还会导致"改了台词却复用旧画面"——v0.4 起指纹不符会**拒绝拼接**并提示删目录 |
| 7 | **JPEG q94 截图替代 PNG**（浏览器方案） | 215 → 55 ms/帧，PSNR 41–44 dB 肉眼无差 |
| 8 | **worker 复用浏览器、出错才重建、finally 必关** | 每块开新页会把进程堆到 28 个、内存 2.7 GB |
| 9 | **前瞻限幅器补响度，不整体拉高** | 只压峰值不改主体响度 |
| 10 | **AAC 编码前预留 1.4 dB 峰值余量** | AAC 会把真峰推高约 0.9 dB |
| 11 | **物理建模激励用加速度不用位移** | click 类质心从 200 Hz 提到 900+ Hz |
| 12 | **每条音效自动出分析图 + QC 阈值** | agent 听不见，但能看图 |
| 13 | **循环环境音用频域整周期噪声** | 首尾天然无缝 |
| 14 | **静态预渲染 + 动态廉价图层 + 相机是裁切窗口** | 单帧从数秒降到可控 |
| 15 | **已验收画法沉淀成构建器函数** | 后写的人只能"调用"不能"发明"，风格一致性靠结构保证 |
| 16 | **Warp 面积累积时间重映射** | 让"后期插入停留"不破坏音画同步 |
| 17 | **段尾必须停住，用逐像素比对验证** | 观众"没看清就被切走"是最常见差评 |
| 18 | **事实核查当独立任务派出去，有编号有黑名单** | 抓到 8 处硬伤，其中 2 处会被评论区顶到第一 |
| 19 | **写入边界 + 接口先写死 + 一份施工文档** | 多 agent 并行不打架的三个前提 |
| 20 | **交付文档如实声明已知边界** | 把"局限"变成可信度，而不是藏起来 |

## 二、16 条反模式（全部有实证）

| # | 反模式 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | 单条 ffmpeg 命令上百个输入混流 | 非确定性静音（三次跑出正常/静音/正常），成片只有前 15 s 有声 | numpy 精确累加 + 分段 RMS 自检 |
| 2 | 以"第几块"命名分块 | 补渲后重号，25 块拼出 417 s（缺 183 s）**且不报错** | 绝对帧号命名（`seg_<起始帧>_<结束帧>.mp4`）+ 排序 + 缺口检测 + 计划指纹 |
| 3 | 用 RMS 近似 LUFS | 误差 6–8 dB，验收形同虚设 | ebur128 / BS.1770 实测 |
| 4 | 先 astype(float32) 再判 dtype | 混音峰值 +92 dBFS | 先判 dtype 再归一 |
| 5 | 把文档数字当验收标准 | README 写 397 cues，产物 370 | 用产物 JSON 反查文档 |
| 6 | 字幕时长按字数比例分配 | 252 处交叠 | TTS 句边界为窗，窗内按标点切 |
| 7 | 场景函数/音频合成/主流程塞进一个文件 | 无场景注册、无并行、无质检、无断点续渲 | 引擎/场景/音频/渲染器四层分离 |
| 8 | PNG 截图做逐帧渲染 | 215 ms/帧 | JPEG q94 → 55 ms/帧 |
| 9 | 每块开一个新浏览器 | 进程累积到 28 个、内存 2.7 GB、渲染卡死 | 长活 worker 复用 + finally 关闭 |
| 10 | 字段改名不留兼容/不跑冒烟 | 全片幕首淡入与图名框**静默失效**，零报错 | 改名后必跑 snap + 元素存在性检查 |
| 11 | 脉冲/位移激励做打击音 | 质心 ~200 Hz，像闷鼓 | 用接触力的二阶导 |
| 12 | QC 判据键名不统一 | `mid_2k6k` / `mid2k6k` 不一致 → 检测恒为 0，等于没检测 | 键名集中定义 + 单测 |
| 13 | 并行写同一批产物 | 读到半成品 mp3 | 产物级串行，或按文件分区 |
| 14 | 音频用单声道总线后复制成双声道 | 损失立体声场 | 全程 float32 立体声（配乐做宽度） |
| 15 | 静态图叠加忘了 `-loop 1` | 时间轴被截成 1 帧 | `-loop 1 -framerate ` |
| 16 | 靠"注意准确性"这种叮嘱做质量 | 无法验收 | 事实核查有编号、出处、黑名单三件套 |

## 三、三个非确定性 bug 复盘（最值得读）

### ① 音轨中断：成片只有前 15 秒有声

**现象**：成片 mp4 开头约 15 秒有声音，之后全程静音。

**根因**：混音用单条 ffmpeg 命令处理 **109 个输入**（55 条配音 + 16 段环境音 + 2 段配乐）。Windows 上 ffmpeg 输入线程池存在竞争：循环输入与大量 `-i` 同时打开时，偶发某个输入尚未就绪就被读取，混音滤镜收到空流，导致后续输出静音。**同样命令连跑三次：正常 / 静音 / 正常。**

**修复**：改为 numpy 精确叠加——每个音源解码为 48k float32 PCM（带缓存）→ 按时间轴精确写入总线 → 归一化 + tanh 软限幅 + 淡入淡出 → 写 WAV，并内置每 20 s 的 RMS 自检。

**教训**：**"确定性"是程序化视频的第一性要求**。任何"同样输入跑两次结果不同"的环节，都要换成纯 numpy/纯 JS 显式实现，并配一个能检出"错了"的自检。

### ② 混音 +92 dBFS

```python
x = x.astype(np.float32)      # ← 先转 float32
if x.dtype == np.int16:       # ← 这个分支永远不成立
    x = x / 32768.0
```

int16 的归一化分支永远执行不到，采样值还是 ±32768 的量级。

**教训**：这类 bug 不报错，只会在"叠加峰值 +92 dBFS"这种数字上暴露 → **混音脚本必须打印中间峰值**。

### ③ 全片淡入静默失效

```js
const localT = t - act.t0;        // undefined
const inP = clamp(localT / 0.5);  // NaN
if (inP < 1 && act.i > 0) { ... } // 永远不成立
```

字段从 `t0` 改名成 `start` 后，全片十幕的淡入特效与所有图名框**静默失效**。没有任何报错，画面照常渲染，只是"少了一点东西"。

**教训**：质检分两类——**"不能有"**（闪烁、重叠、出画、削波）和**"必须有"**（图名框、淡入、字幕、每段至少一个动态元素）。后者更难，因为需要一份"应然清单"。
